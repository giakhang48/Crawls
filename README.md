# SEG301 Assignment 1 — IMDb Real Web Crawler via Local HTML Mirror

## Why this design exists

The assigned source is IMDb. Direct generic crawling of `imdb.com` is currently blocked by IMDb's `robots.txt`, while the assignment explicitly requires respecting crawling restrictions. This project therefore separates **data source** from **crawler mechanism**:

1. IMDb official dataset / previous `imdb.db` supplies the movie records used by a local website backend.
2. `mirror_server.py` exposes those records as real HTML pages over HTTP on `127.0.0.1`.
3. The crawler starts from a Seed URL and retrieves those pages using **Requests**, parses them using **BeautifulSoup**, extracts `<a href>` links, normalizes/filters URLs, manages a **BFS URL Frontier**, enforces depth/page limits, detects exact duplicates, and saves crawl results to SQLite.
4. `validate.py` compares the crawled movie IDs and parsed metadata back to the source catalog to prove completeness and correctness.

The final `data/imdb.db` is therefore generated by a **real Web Crawler**. It is not populated directly from TSV records.

> Important: this is a crawler of a **local IMDb mirror**, not a claim that `www.imdb.com` itself was crawled.

## Mirror topology

```text
Seed /movies/                       depth 0
    ├── /movies/page/1/             depth 1
    ├── /movies/page/2/             depth 1
    └── ...
          ├── /title/tt.../         depth 2
          ├── /title/tt.../         depth 2
          └── ...
```

Because every listing page is linked directly from the root, `MAX_DEPTH = 2` is sufficient to reach every movie. With 757,298 movies and page size 5,000, the complete crawl contains:

- 1 root page
- 152 listing pages
- 757,298 movie pages
- 757,451 total HTTP pages

The exact number is calculated dynamically from your source DB.

## Quick start using your EXISTING 757k imdb.db

Do **not** rebuild/download the 757k corpus again.

```bat
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

python main.py prepare-source --from-db "C:\PATH\TO\OLD\Assignment1\data\imdb.db"
python main.py source-info
```

Now test the crawler on 1,000 real movie records from that source:

```bat
python main.py crawl-test --reset
```

Expected: Requests + BeautifulSoup + BFS run for ~1,002 pages, and `data/imdb_test.db` should validate PASS.

Then crawl the complete local mirror:

```bat
python main.py crawl-full --reset
```

Final output:

```text
data/imdb.db
```

For a faster local run you may try more workers, e.g.:

```bat
python main.py crawl-full --reset --workers 24
```

Do not set a network crawl delay for localhost; the server belongs to this project and no external website is being loaded. The same setting must NOT be copied to an external crawler.

## Validate again

```bat
python main.py validate
```

A complete run should report `RESULT: PASS` and all of these should be zero:

- Missing movies
- Unexpected movies
- Metadata mismatches
- Invalid pages
- Duplicate URL groups
- Duplicate content groups
- Bad crawl depths
- Crawl errors

## Check why direct IMDb crawling is not used

```bat
python main.py imdb-check
```

This only reads IMDb's robots policy and prints ALLOW/BLOCK. It performs no bypass.

## Build source catalog from scratch (optional)

Only use this if you no longer have the old 757k `imdb.db`:

```bat
python main.py build-source
```

This downloads the official IMDb `title.basics.tsv.gz` and `title.ratings.tsv.gz` and builds `data/imdb_source.db`. Again, that source DB is only the backend of the local site; final `data/imdb.db` is still produced by HTTP crawling.

## What is stored in final imdb.db?

### `pages`
Assignment-compatible crawl records: URL, domain, title, visible content, real BFS depth, real HTTP status code, response time, crawl timestamp, fingerprint, page type, canonical IMDb URL.

### `links`
Actual hyperlinks extracted from HTML `<a href>` elements.

### `movies`
Structured fields parsed **from movie HTML pages by BeautifulSoup**: tconst, title, year, runtime, genres, rating, votes, crawled URL, canonical IMDb URL.

### `movie_documents` view
Only movie documents, useful for the next Search Engine assignment. It excludes the root/listing pages.

## Assignment mapping

- Seed URLs / config: `main.py`, `config.py`
- URL Frontier + BFS: `url_frontier.py`, `web_crawler.py`
- Requests + BeautifulSoup: `web_crawler.py`, `parser.py`
- Link extraction/filtering: `parser.py`
- Depth / MAX_PAGES / stopping: `web_crawler.py`
- URL duplicate: `URLFrontier.queued/visited`
- Exact content duplicate: `duplicate.py` SHA-256
- SQLite pages + links: `database.py`
- Statistics: `web_crawler.py`
- Completeness/quality: `validate.py`
- robots.txt: local mirror allows crawler; `imdb-check` documents why external IMDb is not directly crawled.

## Windows WinError 10053 fix (v1.1)
This revision hardens the local HTTP mirror for Windows/Python 3.14:
- listing pages use indexed key-range queries instead of concurrent large OFFSET scans;
- request timeout is 90 seconds;
- each request retries up to 4 times after timeout/connection abort;
- broken/aborted client sockets are handled quietly by the mirror server;
- default workers reduced from 16 to 8 for stability on Windows.

If a machine still has aggressive antivirus/network filtering, run:
`python main.py crawl-full --reset --workers 4`
Completeness validation must end with `RESULT: PASS`.
